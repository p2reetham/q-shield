# Threat Model (Prototype Scope)

## In scope for this SIH demonstration

- Anomalous **signing behavior** around a given key: unusual frequency, odd
  hours, session/device reuse, failed verification attempts, replay indicators,
  and transaction-value outliers.
- **Key lifecycle risk**: very new or heavily overused keys, keys with rising
  failure rates.
- **Signature integrity**: cryptographic verification failures (tampered
  content or mismatched key).
- **Audit-trail tampering**: a broken hash-chain link is detected by the
  blockchain integrity check.

## Explicitly out of scope for this prototype

- Network-level attacks (DDoS, MITM), which would need real network telemetry
  Q-SHIELD does not collect.
- Private-key exfiltration/theft detection outside of its behavioral
  symptoms (a compromised key still has to *sign something* for Q-SHIELD to
  notice).
- Multi-node / distributed blockchain consensus — the ledger here is a single
  local process, not a decentralized network (see `docs/architecture.md`).
- Formal cryptographic certification of the signature scheme.

## Honesty notes

- ML metrics (`backend/ml/models/metrics.json`) are computed on a held-out
  split of **synthetic** data generated by `backend/ml/generate_dataset.py`,
  not real-world signing telemetry. Treat them as a demonstration of a valid
  training/evaluation pipeline, not a real-world accuracy claim.
- The quantum-inspired module is classical (see `docs/quantum_approach.md`).
- The blockchain is a local simulation, not a decentralized ledger.
